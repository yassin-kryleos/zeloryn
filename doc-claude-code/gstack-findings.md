## Eng Review Findings (Codex Outside Voice)

Trigger: `codex exec` via `/plan-eng-review` | Date: 2026-06-17 | Model: OpenAI Codex

### Findings Accepted

| ID | Severity | Finding | Resolution |
|----|----------|---------|------------|
| E1 | **High** | localhost API has no real auth boundary — CORS pinned to localhost does not protect against local processes (curl, malware, another Electron app). Need per-session capability token. | **FIXED** — X-Kryleos-Session token generated by main process, delivered via preload, validated on every backend request (ET1) |
| E2 | **High** | Electron security under-specified — contextIsolation + nodeIntegration:false is necessary but not sufficient. Need: deny untrusted navigation, gate window.open, validate IPC payloads, no raw generic IPC through preload, dev vs prod CSP. | **FIXED** — IPC hardening added (ET4) |
| E3 | **High** | Backend restart semantics can corrupt state — "max 3 restarts" too vague. Need exponential backoff, readiness checks, stderr capture, child PID tracking, no-restart-if-corruption rules. | **FIXED** — supervisor with backoff, readiness ping, corruption guard added (ET2) |
| E4 | **High** | File locking/stale lock cleanup dangerous if underspecified — PID reuse, crashed processes, antivirus, OneDrive sync, file-handle behavior on Windows. Lock needs PID + hostname + process start token. | **FIXED** — lock validation with PID+hostname+start-time (ET5) |
| E5 | **High** | Atomic writes not fully durable — write+rename without fsync is corruptible on power loss on ext4/NTFS. | **FIXED** — fsync added to atomic write path (ET3) |
| E6 | **Medium** | Renderer/backend port handoff is a race-prone contract — if backend restarts on new port, renderer state silently breaks. Use main-process broker. | **FIXED** — main-process broker for port handoff (ET9) |
| E7 | **Medium** | Schema migration needs rollback and forward-compat rules — backup-before-migrate, failed-migration recovery, unknown future-version behavior. | Deferred to Phase 2 (when .kryleos has migration-worthy data) |
| E8 | **Medium** | CI too thin for Electron — npm install → tsc → eslint → jest misses the app boundary. Need at least one Electron smoke test proving boot + preload + health endpoint. | **FIXED** — Electron smoke test added to CI (ET6) |
| E9 | **Medium** | Logging has no redaction or retention policy — traces include paths, git remotes, approval IDs, command args. | Deferred to Phase 5 (when tool calls introduce sensitive data) |
| E10 | **Medium** | Folder picker implies filesystem trust boundaries — selected folder should be canonicalized, symlink-aware. | Deferred to Phase 1 (when picker UI is built) |
| E11 | **Medium** | Package/build reproducibility missing — no locked Node version, package manager, workspace conventions. | **FIXED** — .nvmrc + package manager lock (ET7) |
| E12 | **Low** | /health may leak session details — returning { status, version, session } exposes non-public data. | **FIXED** — /health returns { status, version } only (ET8) |
